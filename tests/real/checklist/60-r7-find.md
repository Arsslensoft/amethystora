# Round 7, the find group: old words, what you remember, holding Super

Walk on a real machine, in the shipped state unless an item says otherwise. The spec is `plans/ui-ideas/r7/spec-find.md`. Mark each
line `→ PASS` or `→ FAIL: what was seen`.

## It speaks your old words (R7-49)

- [ ] R7-FIND-01 Old words lead here. How: `Super+Space`, type `task manager`. Expect: under HERE IT IS, a row with Mission Center's icon and name and "What is running, and what it uses"; `Enter` opens Mission Center. Then the same with `recycle bin` (Trash, In Files: Files opens on the trash), `control panel` (Settings), `print screen` (the screenshot tool opens, nothing left of the search over it), `drivers` (a terminal running `ame system drivers`), `undo an update` (the Manual at Rolling back). Then `print screen` typed in the overview (`Super`, then type): the screenshot tool opens over the desktop, and the picture to cut from is the desktop, not the overview.
- [ ] R7-FIND-02 A word on its way takes nothing, and an app keeps its name. How: `Super+Space`, type `task`, then `antivir`, then `Calcul`, then `bin`, then `console`. Expect: no HERE IT IS row for the first four; `Enter` on `Calcul` opens Calculator as before; `console` shows the terminal row only when no installed app's name starts with `console`. Install any app whose name is one of the table's phrases (or start typing the name of an installed app that is: `Enter` must open that app, never the row's).
- [ ] R7-FIND-03 Your language. How: in a session in French (or German, Spanish, Arabic), `Super+Space`, type `corbeille` (`papierkorb`, `papelera`, `سلة المحذوفات`), then `recycle bin`. Expect: both lead to the trash; the row's words are in the session's language. [needs: a second language installed]
- [ ] R7-FIND-04 An app that is not there. How: `flatpak uninstall io.missioncenter.MissionCenter`, then type `task manager`. Expect: no row offers to install anything. Put it back with `flatpak install flathub io.missioncenter.MissionCenter`. [needs: the network to put it back]
- [ ] R7-FIND-05 Off is as before. How: `ame desktop search old-words off`, type `recycle bin`. Expect: no HERE IT IS row at once, without a re-login; Control's Desktop page, Search group, shows "Words you already know" off. `ame desktop search old-words on` brings it back at once.
- [ ] R7-FIND-06 No other maker's name. How: read the rows above, then look through the table in `/usr/share/gnome-shell/extensions/amethystora-ui@arsslensoft.github.io/modules/search/words.js`. Expect: everyday words only, bar the four old names (task manager, control panel, recycle bin, print screen); the build's own test already fails on a list of names, in English and in the four catalogs, this is the human look. Type `device manager`, `disk cleanup`, `system restore`, `sticky notes`: none gives a HERE IT IS row.

## Find it by what you remember (R7-60)

- [ ] R7-FIND-07 A kind and a date. How: put a PDF in Downloads, touch it to last week (`touch -d "last wednesday -7 days" ~/Downloads/lease-test.pdf`), wait for the indexer (`localsearch info ~/Downloads/lease-test.pdf`), then `Super+Space`, `pdf from last week`. Expect: under BY WHAT YOU REMEMBER, `lease-test.pdf` with `Downloads · ` and its date, and the line "Also understood: kinds of file, dates and sizes."; `Enter` opens it. It shows within a moment of the last key.
- [ ] R7-FIND-08 Sizes and names. How: `big videos`, `photos yesterday`, `lease from` and this month's name, `lease over 1 kb`, `3 days ago`. Expect: each lists only files that fit, biggest first for `big videos` with the size in the row, newest first otherwise; a word it cannot read has to be in the file's name.
- [ ] R7-FIND-09 Your language. How: in a French session, `pdf de la semaine dernière`, `photos d'hier`, `vidéos plus de 1 go`, `pdf de mardi`. Expect: the same as in English; a weekday or month is read in the session's language, and English still works. [needs: a second language installed]
- [ ] R7-FIND-10 Words it cannot read. How: `holiday plans`, `1284 * 0.18`, `2024`. Expect: no BY WHAT YOU REMEMBER section, and search behaves as usual (the sum answers); `pgrep -f amethystora-file-find` never finds one for them.
- [ ] R7-FIND-11 Never the Private folder, and not in GNOME's index. How: `gsettings get org.freedesktop.Tracker3.Miner.Files ignored-directories` must end with `'Private'`. Then `ame security private-folder open`, put a `secret-test.pdf` with the word `secretcanary` in it into `~/Private`, wait two minutes, and: `localsearch info ~/Private/secret-test.pdf` (must say there is no metadata for it), `localsearch search secretcanary` (nothing), `Super+Space` and `secret pdf` and `pdf` (not in BY WHAT YOU REMEMBER, and not in GNOME's own Files row), and `grep -rl secretcanary ~/.cache/tracker3 ~/.local/share/tracker 2>/dev/null` (nothing). On a machine that had the folder open before this image, the index forgets it within a minute of the update: look again after a minute. Also type `pdf` with 30 newer PDFs in `~/Private` and older ones outside it: the older ones still show. [needs: the Private folder set up]
- [ ] R7-FIND-12 Nothing kept. How: type `pdf canaryword-find-12 from last week`, close the box, then `grep -rl canaryword-find-12 ~ /tmp /var/tmp 2>/dev/null; journalctl -b | grep -c canaryword-find-12`, and, with Security's EXEC_WATCH on if you use it, `sudo ausearch -m EXECVE | grep -c canaryword-find-12`. Run the grep with the shell's history off (`set +o history`), or expect only your own history file to hold the word. Also open a remembered file that has since been deleted (Enter on its row after `rm`): the journal line says an error number and no file name (`journalctl -b | grep "did not open"`). Expect: no file, 0 and 0: the words go to the helper on standard input.
- [ ] R7-FIND-13 Idle and off. How: with the box closed, `pgrep -f amethystora-file-find` several times; then `ame desktop search remembered off` and type `pdf from last week`. Expect: no process while nothing is typed and it ends after each search; off, no section at once and no process at all, and GNOME's own Files row is unchanged.
- [ ] R7-FIND-14 One word is left to the apps. How: type `photos`, then `music`, then `today` (and in a French session `aujourd'hui`, `l'image`). Expect: no BY WHAT YOU REMEMBER section, and `Enter` is what it was (an app); with `pdf from last week` the section comes above the apps and `Enter` opens the first file. An installed app's name wins: with an app named `Document Scanner` (Simple Scan is `Document Scanner`) and a file `scanner-manual.pdf`, type `document sc` and `document scanner`: no file row, `Enter` opens the app. Know this: for about a second after the last key (GNOME's 150 ms, 250 ms of quiet and the index's 0.5 to 0.8 s) `Enter` still opens what GNOME's own app search found first, and the file row arrives and takes the selection then; the app-name rule only keeps it off an app that is being typed.
- [ ] R7-FIND-20 Dates that cannot be read are not answered wrongly. How: type `monday last week` (Monday of last week), `since last week` (files from last week until now), `march 5` (the 5th of March), `report 2024 pdf` (a pdf with 2024 in its name, from any year), `monday march` and `today yesterday` (neither gives a BY WHAT YOU REMEMBER section). Expect: as written.
- [ ] R7-FIND-21 A name that is not UTF-8 does not empty the section. How: `touch ~/Downloads/$'bad\xff-test.pdf' ~/Downloads/good-test.pdf`, wait for the indexer, type `pdf from today`. Expect: `good-test.pdf` is there; the other is not. Delete both.

## Hold a key to see the keys (R7-62)

- [ ] R7-FIND-15 The hold. How: hold `Super` alone for a second over a window. Expect: the card says HOLDING SUPER, shows the common shortcuts with Emoji `Super+.` among them, "Let go and it disappears. Control has every shortcut.", and the dock's numbers; letting go fades it, no overview. On a real GPU the card appears and fades smoothly. [needs: a GPU]
- [ ] R7-FIND-16 The tap is unchanged. How: tap `Super`; hold it half a second and let go; `Super+E` during a hold; after `ame desktop keyboard super search`, tap it again and put it back with `ame desktop keyboard super overview`. Expect: the overview opens on a tap (the search box when so set); a short hold opens it too and shows no card; a shortcut shows nothing.
- [ ] R7-FIND-17 Your own keys. How: `ame desktop shortcut` to change the emoji key, or `gsettings set org.gnome.shell.extensions.amethystora-ui.emoji emoji-picker "['<Super>semicolon']"`, then hold Super; put it back with `gsettings reset`. Expect: the card shows the new key the next time; with an empty list the Emoji row is not there.
- [ ] R7-FIND-18 Off is as before. How: `ame desktop windows hold-super off`, hold `Super` for two seconds, let go. Expect: no card, and the overview opens on release as GNOME's does. Turn it on again with `ame desktop windows hold-super on`.
- [ ] R7-FIND-19 RTL. How: hold `Super` in an Arabic session. Expect: the card reads right to left and nothing is cut; the keys read left to right. [needs: Arabic installed]
