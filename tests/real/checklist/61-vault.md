# The Vault

Walk on a real machine with the beta image, as a person would. The design is `plans/done/PLAN-vault.md`, the manual `vault.md`, and the lab's
checks `tests/vm/suites/74-vault.sh`. Every approval is polkit's question, answered with the account's own password: an item that needs one
needs the person at the machine. Mark each line `→ PASS` or `→ FAIL: what was seen`.

## The third walk (2026-11-09, beta-45.20261109 at 0626505b, a throwaway account)

The maintainer's vault opens only with its recovery key (V-24), so this walk set up a vault on a throwaway account, `vaulttest`, removed
after. It had no seat session, so a login session was held open with `machinectl shell`, and a polkit rule of its own (in `/etc`, removed
with it) asked for its own password outside a seat, as `allow_active` asks on one. Questions went to `pkttyagent` registered for the
asking program itself: one registered for the session, or for a parent shell, was not asked when the service gave polkit the program as a
pidfd. No SELinux denial in the whole walk; the service's memory peaked at 6 MB.
