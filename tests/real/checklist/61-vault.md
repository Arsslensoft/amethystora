# The Vault

Walk on a real machine with the beta image, as a person would. The design is `plans/PLAN-vault.md`, the manual `vault.md`, and the lab's
checks `tests/vm/suites/74-vault.sh`. Every approval is polkit's question, answered with the account's own password: an item that needs one
needs the person at the machine. Mark each line `→ PASS` or `→ FAIL: what was seen`.

## As shipped

- [x] V-01 Nothing runs. How: `systemctl status amethystora-vault.socket amethystora-vault-ssh.socket amethystora-vault.service amethystora-vault-net.socket`, `systemctl list-timers --all | grep -i vault`, `systemctl cat amethystora-vault.service`. Expect: both sockets enabled and listening, the network service's socket only, the service inactive, no timer; the unit has `PrivateNetwork=yes`, `CapabilityBoundingSet=`, `MemoryDenyWriteExecute=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `SystemCallFilter=@system-service`, `LimitCORE=0`, `LogLevelMax=warning`; the user `amethystora-vault` exists and its state folder is 0700. → PASS (real machine, beta-45.20261103 with main on the /usr overlay): both sockets and the network socket enabled and listening, the service inactive, no timer, every hardening line in the unit, the user and its 0700 folder
- [x] V-02 It goes away. How: `ame vault status`, then wait. Expect: the service starts on the call and is inactive again within about a minute of the last call, with no vault open. → PASS (real machine, beta-45.20261103 with main on the /usr overlay): started by a status call at 06:14:48 and inactive at 06:18:00, about a minute after the last call
- [x] V-03 The cold start. How: `time ame vault status` with the service stopped; send a line that is not a request to `/run/amethystora/vault.sock`, then a status. Expect: an answer well under a second; the bad line gets `bad-request` and the next is answered. → PASS (real machine, beta-45.20261103 with main on the /usr overlay): 0.26 s through the CLI, 40 ms through `ame vault status`; a bad line got bad-request and the next status was answered. This account already has a vault, so the words for none were not seen
- [x] V-04 Every command answers. How: `ame vault status`, `ame vault vaults`, `ame vault methods`, `ame vault lock`. Expect: each answers in its own words, no shell error; with the vault closed, those that need it open say so. → FIXED c4bce9c9: every `ame vault` command died with "syntax error near unexpected token `||'" (a blank line ended the line continuation in the recipes' shared shell); they answer now, and test-vault.sh parses that shell
- [x] V-05 Generators need nothing open. How: `/usr/libexec/amethystora-vault-cli password generate`. Expect: a password, with no vault open and no question. → PASS (real machine, beta-45.20261103 with main on the /usr overlay): a password, no vault open, no question
