# Round 7: it tells you the truth

R7-37 Is it me or the internet?, R7-38 A USB stick that tells the truth, R7-39 What happened while it slept, R7-53 A warning before
the disk dies (`plans/ui-ideas/r7/spec-truth.md`). Walk them on a real machine as a person would. Mark each line `→ PASS` or `→ FAIL: what was seen`.
These ideas exist to say true things: a sentence that claims more than the machine knew is a failure, even when it happens to be right.

## R7-37 Is it me or the internet?

- [-] R7-TRUTH-01 All fine, on Wi-Fi. How: on a working Wi-Fi network, open quick settings and the Wi-Fi tile's menu. Expect: at the top of the menu, You, Router and Internet joined by two green lines, within two seconds; the sentence says the computer and Wi-Fi are fine and the internet answers; the card is there the moment the menu opens, with "Looking…" for an instant. [needs: Wi-Fi] → N/A: desktop on Ethernet only, no Wi-Fi
- [-] R7-TRUTH-02 The line beyond the router. How: unplug the router's internet cable (or the phone's mobile data if it is a hotspot), wait a minute, open the menu. Expect: the first line green, the second red; the sentence says your router may not be reaching the internet, and to try restarting it. [needs: a router you can unplug] → N/A: needs router to unplug; real network in use
- [-] R7-TRUTH-03 The line to the router. How: stay connected while the router's power is cut, or walk far enough that it stops answering while the Wi-Fi still shows connected, and open the menu. Expect: the first line red (or green with the second red if the router still answers at the link); the sentence says the router does not seem to answer, that it may be off or out of range, and to move closer or restart it, never that it is certainly down. [needs: a router you can unplug] → N/A: needs router to unplug
- [-] R7-TRUTH-04 A sign-in page. How: join a network that wants a login (a hotel's, a train's, or a test portal). Expect: the second line amber, and the sentence says to sign in first. [needs: a captive portal] → N/A: needs captive portal
- [x] R7-TRUTH-05 A wired connection. How: on a cable, open quick settings' Wired menu. Expect: the same drawing; the sentences speak of the cable. [needs: Ethernet] → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay): Wired menu in my shell: You-Router-Internet two green lines, 'Your computer and its cable are fine, and the internet answers.'
- [x] R7-TRUTH-06 It contacts only what it says. How: in a terminal, `sudo tcpdump -ni any 'icmp or icmp6 or port 53 or port 853'`, open the menu once and close it. Expect: one ping to the router and its reply; one lookup, of the host in the `uri=` line of `/usr/lib/NetworkManager/conf.d/*connectivity*.conf`, to your name server, and nothing else from it; nothing further while the menu stays closed. → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay): tcpdump while opening Wired menu once: one ICMP echo+reply to 10.0.0.1, A+AAAA lookup of fedoraproject.org (the uri host) to 10.0.0.1:53; other DNS in capture was the machine's own browsing
- [-] R7-TRUTH-07 A router that ignores pings. How: on a network whose gateway drops ICMP. Expect: both lines green when the internet answers; with the internet down the sentence blames the router with "may", not as a fact. [needs: such a router] → N/A: no ICMP-dropping router
- [x] R7-TRUTH-08 Off. How: `ame desktop network-check off`, open the menu; `ame security sends`. Expect: GNOME's own menu with no drawing, and no ping in tcpdump; sends says it is off. Put it back: `ame desktop network-check on`. Control's Network group shows the same switch. → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay): network-check off: menu is GNOME's plain list, 0 ICMP in tcpdump; ame security sends says 'Where a connection breaks: off'; put back on. Control's switch not looked at
- [ ] R7-TRUTH-09 Encrypted DNS. How: `ame security dns on cloudflare` (or the one you use), open the menu. Expect: still fine, and the lookup goes over port 853 only. Put it back. → NOT DONE: changes real system DNS (ame security dns on) on the shared machine; not done
- [ ] R7-TRUTH-30 Encrypted DNS blocked. How: with encrypted DNS on, join a network that blocks port 853 (or `sudo nft add rule ...` to drop it) while the internet otherwise works, open the menu. Expect: the first line green, the second amber, and the sentence says the internet may be reachable but the name server did not answer, and that encrypted DNS is on and the network may be blocking it; not that the router should be restarted. Put it back. [needs: a way to block port 853] → NOT DONE: needs encrypted DNS on and an nft drop on the real machine
- [ ] R7-TRUTH-31 The connectivity check off. How: `ame security connectivity-check off`, open the Wi-Fi menu with tcpdump as in R7-TRUTH-06. Expect: one ping and no name lookup at all; the drawing says only what the router said ("Your router answers. Whether the internet does could not be asked."), and a silent router is not called down. Put it back with `ame security connectivity-check on`. → NOT DONE: ame security connectivity-check off changes real NetworkManager config; not done
- [-] R7-TRUTH-32 Another connection. How: on a machine with a cable and Wi-Fi both connected, open the Wi-Fi menu (the cable is the default route; or the other way round). Expect: only the first line is drawn, the second blank, and the sentence says this is not the connection the computer uses for the internet; no name lookup is made for it. [needs: two connections] → N/A: only one connection (Ethernet)
- [x] R7-TRUTH-33 Nothing kept. How: after opening the menu a few times on a network with a recognisable gateway address, `grep -rl "$(ip route | awk '/default/{print $3; exit}')" ~ /tmp 2>/dev/null; journalctl -b | grep -c "$(ip route | awk '/default/{print $3; exit}')"`. Expect: only what you put there yourself and what GNOME or NetworkManager writes; nothing of ours in `~/.local/state/amethystora`, no journal line from the shell. → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay): after opening menu: nothing in ~/.local/state/amethystora mentions gateway 10.0.0.1; 0 gnome-shell journal lines with it (did not run the full /tmp grep or system-wide journal count)

## R7-38 A USB stick that tells the truth

- [-] R7-TRUTH-10 A big copy. How: plug in a USB stick formatted exFAT or ext4, and copy a few GB to it in Files. Expect: the pill soon says "Still writing to “NAME” · about N%", with a fill growing from its start; the number never goes down; it keeps saying so after Files says the copy is done, for as long as the stick's light keeps flashing. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-11 All there. How: wait for R7-TRUTH-10 to end. Expect: "All on “NAME”", for about eight seconds, only once the stick's light has stopped; `sync -f` on its mount from a terminal returns at once at that point, and `lsof +D /run/media/$USER/NAME` shows nothing of yours. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-12 The card. How: click the pill while it writes. Expect: "Not safe to unplug yet" and about how much is waiting, at once; below it the programs holding the disk, or that nothing of yours is. **Put it away** ejects it once it is done, and the pill then says it is safe to unplug. Leave the card open while the copy ends: its two sentences change to "Everything is on" by themselves, and back if you start another copy. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-13 Refused. How: open a picture on the stick in Image Viewer, or `cd` into it in a terminal, then Put it away in the pill's card. Expect: it stays mounted, a notice says it could not be put away, and the list names Image Viewer or the terminal, with Quit, which closes it only when pressed. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-14 Reading says nothing. How: copy a file from the stick to the home folder. Expect: no "Still writing". [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-15 An encrypted stick. How: as R7-TRUTH-10, on a LUKS stick. Expect: the same. [needs: a LUKS stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-16 No cost when left alone. How: leave a stick mounted, touch nothing for two minutes, then `sudo strace -f -c -e trace=openat,ppoll,epoll_wait -p $(pgrep -x gnome-shell)` for 60 seconds with the pointer left alone, and again with the pointer moved once a minute (compare with no stick mounted). Expect: nothing extra while nothing moves; once moved, one read of `/proc/meminfo` every 15 seconds (30 after a minute), the stick's own `stat` only when you wrote something, and the added wakeups well under the 40 a minute the plan allows. With no stick mounted, nothing ever; with a stick mounted read-only (an installer stick), nothing. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-17 Off. How: `ame desktop usb-writes off`, copy to the stick. Expect: the pill says nothing and the clock stays; Files and its eject behave as GNOME's. Put it back: `ame desktop usb-writes on`. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-18 The name stays in memory. How: name a stick CANARYSTICK, write to it and open the card, then `grep -rl CANARYSTICK ~ /tmp 2>/dev/null; journalctl -b | grep -c CANARYSTICK`. Expect: only what you put there yourself (recent files, GNOME's own); nothing of ours in `~/.local/state/amethystora`, and no journal line from the shell. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-34 A slow source. How: copy to the stick from something slow (a throttled network share, a phone over MTP, or `pv -L 2M big.iso > /run/media/$USER/NAME/big.iso`), so that data arrives for minutes at a few MB a second. Expect: the pill says "Still writing" throughout, and never "All on" until the copy has ended and the stick's light has stopped, including in the moments right after the kernel has flushed a batch. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-35 A second copy. How: let “All on” show, then at once start another copy to the stick. Expect: the pill goes back to "Still writing" within a few seconds; it never stays on “All on” over a running copy. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-36 Something still has it open. How: in a terminal, `cd` into the stick and `sleep 600 > keep.tmp &` (a program holding a file open), copy a file to the stick in Files and wait for it to settle. Expect: the pill never says “All on”; it says "Something is still using “NAME”" and the card lists the terminal. Close it: after a few seconds the pill proves it again and then says “All on”. [needs: a USB stick] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-37 A file system that cannot be proved. How: format a stick NTFS and mount it through `ntfs-3g` (`mount | grep fuseblk` shows it; some systems use the kernel driver instead, which is then provable), copy to it. Expect: the pill never says “All on” for it: it stays on "Still writing" until you Put it away. [needs: an NTFS stick through ntfs-3g] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-38 A drive with two partitions. How: a disk or stick with two partitions both mounted, **Put it away** from the pill. Expect: the notice says "Safe to unplug" only once both are gone (`lsblk` shows neither mounted); if one stays mounted it says the rest of the drive is still in use instead. [needs: a drive with two partitions] → N/A: no USB stick attached (lsblk shows only NVMe)
- [-] R7-TRUTH-39 A stick that hangs. How: write to a stick, then pull it half way (or one that hangs on writes). Expect: the pill never says “All on”, no pile of `sync` processes (`pgrep -c sync` stays at most 1 per stick), and nothing keeps ticking after the stick is gone. [needs: a stick you can pull] → N/A: no USB stick attached (lsblk shows only NVMe)

## R7-39 What happened while it slept

- [-] R7-TRUTH-19 A night with a loss. How: on a laptop on battery, charge above 50%, suspend overnight (or long enough to lose ten points). Open it, unlock. Expect: within seconds of the unlock a notice "N% gone while it slept", saying how many times it woke by itself and when, that it did not say what woke it, or that nothing woke it only when the journal showed exactly one wake, yours; "It did not say why." otherwise. Said once: lock and unlock again, and nothing more. [needs: a laptop that loses 10 points in sleep] → N/A: desktop, no battery (M910q)
- [-] R7-TRUTH-20 Something woke it. How: leave a wireless mouse able to wake it, and close the lid with the mouse moving now and then through the night. Expect: the notice names a USB or Bluetooth device and offers **Stop it waking the computer**. [needs: a laptop, a mouse that wakes it] → N/A: desktop, no battery (M910q)
- [-] R7-TRUTH-21 Stop it, and undo. How: press Stop it waking the computer, give the password, then suspend and move the mouse. Expect: the mouse no longer wakes it, also after a restart; `ame system wake-device` lists its ID and name; the watcher says nothing of `/etc/udev/rules.d/90-amethystora-wake.rules` (`ame security events`). Undo, or `ame system wake-device on ID`, brings it back and removes the file. [needs: a laptop, a mouse that wakes it] → N/A: desktop, no battery (M910q)
- [-] R7-TRUTH-22 An ordinary night. How: a night losing a few points. Expect: nothing is said. [needs: a laptop] → N/A: desktop, no battery (M910q)
- [x] R7-TRUTH-23 Without a battery. How: a desktop computer, suspended and woken. Expect: nothing said, and no `amethystora-sleep-report` run (`journalctl -b | grep sleep-report`, and `ps` while it wakes). → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay): desktop: journalctl -b has 0 sleep-report lines, no sleep-report.json exists; not suspended (forbidden), so only the no-battery idle state was seen
- [-] R7-TRUTH-24 Off. How: `ame desktop power sleep off`, then a night as R7-TRUTH-19. Expect: nothing said, and `~/.local/state/amethystora/sleep-report.json` is not changed. Put it back: `ame desktop power sleep on`. [needs: a laptop] → N/A: desktop, no battery (M910q)
- [-] R7-TRUTH-25 What is kept. How: after a notice, `cat ~/.local/state/amethystora/sleep-report.json`. Expect: 0600, a salt and checksums only; no device name or ID; the device's name in nothing but the notice (`grep -r "NAME" ~/.local/state/amethystora`). [needs: a laptop] → N/A: desktop, no battery (M910q)
- [-] R7-TRUTH-40 Your own key is never blamed. How: suspend with a USB keyboard or mouse attached and able to wake it, wait over half an hour with nothing else touching it, wake it with a key press or a mouse move, as a person does (needs the battery to have lost ten points; run it overnight on a laptop). Expect: that keyboard or mouse is not named, and **Stop it waking the computer** is not offered for it. [needs: a laptop that loses 10 points in sleep] → N/A: desktop, no battery (M910q)
- [-] R7-TRUTH-41 Nothing known is not "nothing woke it". How: as R7-TRUTH-19 from an account that is not an administrator (it cannot read the journal). Expect: the notice says "It did not say why."; never that nothing woke it, and no Stop button. [needs: a laptop, a non-administrator account] → N/A: desktop, no battery (M910q)
- [-] R7-TRUTH-42 A long lock before sleep. How: lock the screen, leave the laptop awake and busy on it for 25 minutes (a build or a download), then let it sleep a short while (40 minutes). Expect: no "gone while it slept" notice that blames sleep for the 25 minutes' use. [needs: a laptop] → N/A: desktop, no battery (M910q)
- [-] R7-TRUTH-43 The way back in Control. How: after R7-TRUTH-21, dismiss the notice, open Control, System: Sleep. Expect: an entry "Let NAME wake the computer again" with its ID, which runs `ame system wake-device on ID` in a terminal; after it, the entry is gone. [needs: a laptop, a mouse that wakes it] → N/A: desktop, no battery (M910q)
- [x] R7-TRUTH-44 A hub is never stopped. How: `sudo /usr/libexec/amethystora-sleep-report stop usb:1d6b:0002`, and the same for your USB controller's PCI ID (`lspci -nn | grep -i usb`). Expect: refused with "That stands for every device behind it", no file in `/etc/udev/rules.d`.  → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay, second pass): `sudo amethystora-sleep-report stop usb:1d6b:0002` and `stop pci:8086:a2af` (the xHCI controller): "That stands for every device behind it, so it is not stopped.", exit 78, nothing in /etc/udev/rules.d
- [ ] R7-TRUTH-45 The device's name stays in the notice. ## R7-53 A warning before the disk dies

- [x] R7-TRUTH-26 It reads. How: after ten minutes up, `ame system disk-warning`. Expect: says it is on, and one line per system disk naming what it reports (not "does not say how it is" on a disk that has SMART: that line would mean the hourly service cannot read the disks); `/var/lib/amethystora/disk-health.json` is readable by all and holds the model, a checksum of the serial (never the serial itself), the state and counts. `systemctl list-timers amethystora-disk-health.timer` shows the hour. Then `sudo systemctl start amethystora-disk-health.service; sudo journalctl -u amethystora-disk-health -b` shows no error. → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay): ame system disk-warning: 'on' + 'KXG60ZNV256G NVMe TOSHIBA 256GB: reports nothing wrong'; disk-health.json 0644 with model, 32-hex serial checksum (not the real serial), state passed, errors 0; timer hourly next 07:02; service start ran, journal clean
- [x] R7-TRUTH-27 A disk that says it is failing. How: on a disposable disk that fails SMART, or with `smartctl` swapped by a stand-in in a test install (`sudo mount --bind /tmp/fake /usr/sbin/smartctl`), then `sudo systemctl start amethystora-disk-health.service`. Expect: a notice "Your disk says it is failing", using "may"; days since your last backup or that you have none (nothing about backups if the stamp could not be read); **Tell me more** opens the manual's section, **Back up now** starts the backup and opens Backups. Said once: a second start says nothing. [needs: a failing disk or a stand-in] → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay, second pass): with test-disk-health.sh's stand-in smartctl against the installed helper: a failing disk told once ("told /dev/sda failed"), a second check silent, errors after failing add nothing. The notice's words and buttons not seen on screen
- [-] R7-TRUTH-28 A disk asleep stays asleep. How: if the system is on a spinning disk, `sudo hdparm -y DISK`, start the service, `sudo hdparm -C DISK`. Expect: still standby, and the state file keeps what it said last. [needs: a spinning system disk] → N/A: system disk is NVMe, not spinning
- [x] R7-TRUTH-29 Off. How: `ame system disk-warning off` (or Control's System page, Disks). Expect: the timer is disabled and smartctl is not run: `systemctl list-timers` no longer lists it; `on` brings it back. → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay, second pass): `ame system disk-warning off`: the timer disabled and gone from `systemctl list-timers --all`, with "The system's disk is no longer read. Nothing will warn you before it fails."; `on`: enabled and listed, next in an hour
- [x] R7-TRUTH-46 An old bad sector is not news. How: on a disk that already counts a reallocated sector (or the stand-in with `5` raw 1), delete `/var/lib/amethystora/disk-health.json` and start the service. Expect: no notice, the file shows `errors` 1 and the state `errors`; a later rise to 2 gives one notice. [needs: a disk with an old bad sector or a stand-in] → PASS (headless GNOME Shell 51 on the real machine, beta-45.20261103 with main on the /usr overlay, second pass): stand-in smartctl: a disk first read with a reallocated sector (5 raw 1, 197 raw 1) gives no notice, the state file says errors 2 and state errors; a rise to 3 is told once. The case added to test-disk-health.sh (b6927306)
- [-] R7-TRUTH-47 One voice for a pool. How: on a system with a btrfs over two disks (`ame system raid status` lists them), make `smartctl` say the first is failing, start both `amethystora-raid-check.service` and `amethystora-disk-health.service`. Expect: one notice, from the pools' check ("A disk of the system is failing", with what to do), none from the disk warning. On LVM or md over two disks (no pool), the disk warning says it. [needs: a stand-in smartctl; two disks] → N/A: single disk, no pool
- [-] R7-TRUTH-48 Two NVMe disks swap names. How: on a machine with two NVMe disks, after a first notice for one, restart until the names `nvme0n1` and `nvme1n1` swap (or make the stand-in swap them). Expect: the disk with errors is not told again as new. [needs: two NVMe disks] → N/A: one NVMe disk only
